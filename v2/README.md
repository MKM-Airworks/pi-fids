# Pi-FIDS V2

初期対象はSHI・ROR。既存Windows端末のOSを入れ替えず、Raspberry Piと共通の受信・表示処理を使います。V2はGoogle Sheetsを使用しません。

このブランチには、Mac上で確認できる初期試作があります。リポジトリ直下のV1コードは保全し、V2はこのディレクトリ内で開発します。

## 初期試作の起動

Python 3.9以上で、追加ライブラリなしで起動できます。

```sh
cd v2
python3 -m pifids
```

管理画面は `http://127.0.0.1:8800/`、表示画面は `http://127.0.0.1:8800/display?airport=SHI` です。RORは空港指定を `ROR` に変更します。データは標準で `~/.pifids-v2/prototype.sqlite` に保存します。`--database` と `--port` で変更できます。

試作ではSHI/ROR別の便追加、下書きと公開の分離、公開版の永続保存、便ごとの言語順序、表示側の空港ロゴURL・言語・切替秒数を確認できます。画面文言の言語切替に対応し、行先名の翻訳データはまだ未実装です。

既定はlocalhost限定の試作です。管理ログインと端末認証付きの読取専用LAN配信を追加しました（下記参照）。MKM Flight Webの手動取得・下書き取込みを追加しました。正本切替、Webメインの自動適用、Windows配布と実機検証は未実装です。ロゴURLは表示確認用で、正式な画像配信の実装ではありません。

```sh
cd v2
python3 -m unittest discover -s tests
```

## 構成

| 領域 | 役割 |
| --- | --- |
| `manager/`（実装予定） | ローカル編集・公開、LAN配信、表示指示、保存、復旧 |
| `client/`（実装予定） | 共通受信、キャッシュ、便一覧・カウンター・搭乗口表示 |
| `shared/`（実装予定） | データ契約、検証、空港時刻、公開版識別 |
| `cloud/`（実装予定） | Webメイン、バックアップ受付、復旧、正本管理 |

| `docs/` | 設計と開発順序 |

## 対応対象

- Windows 10 x86 / x64
- Windows 11 x64
- Raspberry Pi（OS・機種を実機検証時に確定）

Windowsの配布パッケージと実行環境はx86/x64を分けます。互換性はまだ未検証です。Macでは共通機能の開発を先行します。

詳細は[設計方針](docs/architecture.md)と[開発順序](docs/roadmap.md)を参照してください。

## 端末ごとの表示切替

管理画面で画面ID、カウンター／搭乗口、航空会社名を指定します。対象画面は `/display?airport=ROR&displayId=gate-01` のように開き、約5秒間隔で指示を取得します。「標準の便一覧に戻す」で解除できます。空港・画面IDごとに指示を永続保存します。端末のローカル設定も画面ID別です。航空会社表示は文字のみの初期実装です。便割当、クラス、矢印、端末からの反映応答は未実装のため、適用後は対象画面で確認します。

## ロゴ・案内画像の登録と端末保存

管理画面でPNG/JPEG（1画像2MiBまで、空港ごと30画像まで）を登録し、画面IDにロゴ・案内画像を割り当てます。画像はDBに元バイトを保存し、SHA-256をIDとして配信します。新しい表示指示は必要画像の取得・SHA-256確認・ブラウザへの保存に成功してから反映します。失敗時は直前の表示を保持します。同じIDの画像の上書きはありません。

表示端末はCache Storageに画像、localStorageに最後の公開便と表示指示、Service Workerに表示画面を保存します。一度正常受信した同一URL・同一ブラウザでは、サーバー停止中の再読み込みでも復元できます。保存前の初回起動、ブラウザデータ削除・容量不足・保存の自動消去では復元できません。管理画面の編集はオフライン対応しません。

現状はlocalhost専用です。LANのHTTPではService Worker等の保存機能を利用できないため、本番のWindows/Piクライアントは端末内のlocalhostで表示する構成、またはHTTPSの構成を別途実装・検証します。ブラウザ保存は専用クライアントのディスク保存実装を置き換えるものではありません。画像のサーバー検証は形式のヘッダーとサイズの確認までで、完全な画像デコード検証・JPEG解像度検証は未実装です。画像削除とキャッシュ整理は未実装です。

Macブラウザでは、試験画像を登録APIでアップロードし、管理画面から割り当て、表示、サーバー停止後の再読み込み復元を確認しました。ファイル選択によるアップロードUIとWindows実機は未検証です。既存V1とMKM Flight WebのAPIに変更はありません。

## 全画面表示・Kiosk運用

本番のWindows表示端末はEdge Kioskで起動し、全画面ボタンを押す運用にはしません。[起動スクリプトと運用方針](deploy/windows/README.md)を参照してください。`&kiosk=1` を指定した表示画面は操作欄を隠し、画面全体に追従します。以下の全画面ボタンはMac等での開発確認用です。

Edge KioskはInPrivateで動くため、ブラウザ再起動をまたぐオフライン保持には端末受信サービスのディスク保存を使います。[端末受信サービス](docs/receiver.md)を追加しました。Macで受信サービスの再起動後の保存復元を確認済みですが、Windows Kioskの実機検証はこれからです。

表示ページは画面全体に合わせ、通常は設定・版情報・試験用案内を隠します。開発用の通常画面では右下の「全画面表示」でブラウザの全画面に入り、Escで解除します。設定は「表示設定」またはURLに `&setup=1` を追加して開きます。便一覧は標準8便ずつ、15秒間隔で自動ページ切替します。

Hanoiの画面サンプルと航空会社ロゴを参照して、便一覧・ロゴ・全面画像の3種類に再構成しました。詳しくは[表示テンプレート](docs/display-templates.md)を参照してください。

ブラウザの制約によりボタンでの開始はクリックが必要です。電源投入後の自動全画面はWindows/Piの自動起動・キオスク設定で対応する予定で、まだ未実装です。表示画面のレイアウトはブラウザ枠が残る状態でも画面サイズに追従します。

管理画面は英語が初期表示です。上部のLanguage選択で日本語へ切替でき、選択を管理PCに保存します。便一覧は定刻・予定時刻・行先／出発地・航空会社・便名・ゲート・備考の順です。Check-in列はなく、出発タイトルは青、到着タイトルは赤です。V2側の任意入力項目として実装し、MKM Flight Web既存APIは変更していません。

## 登録便の編集・削除

下書きの各便にあるEdit／編集で、時刻・出発／到着・ゲート・備考・ロゴ・表示言語などを変更し、Save changes／変更を保存で保存します。Delete／削除は確認ボタンで確定します。編集・削除はいずれも下書きだけに反映し、Publish draft／下書きを公開するまで公開済みの便と表示端末は変わりません。編集のキャンセルと空港の変更では入力中の編集を終了します。

便名が重複していても個別IDで対象を特定します。編集開始後や削除確認中に別の管理画面で下書きが変更された場合は、競合として拒否します。最新の下書きで対象便を選び直してください。既存試作DBの下書きには起動時にIDを補完し、公開済みデータと公開版番号は維持します。

## CA証明書が不要なLAN配信

管理画面は管理PC自身のlocalhostに限定し、別ポートに端末専用の読取配信を開きます。端末は接続ファイルを使って公開便・表示指示・画像を受信し、端末内のlocalhostでブラウザ表示します。CA証明書やHTTPS設定は不要です。管理ログインは英語を初期表示にし、日本語へ切替できます。設定した空港だけ管理・受信できます。

導入設定・接続キーの発行と失効・通信の前提は[LAN配信手順](docs/lan.md)を参照してください。HTTP配信は暗号化しないため、信頼できる閉じた空港LANが前提です。Mac上で別ポートの管理・配信・受信サービスを使った通信試験を実施しました。異なるPC間とWindows実機の検証はこれからです。

## MKM Flight Webの出発・到着を取込む

管理PCで既存の出発ダイヤ、または新設したFIDS専用の出発・到着配信を取得し、運航日ごとの便を下書きへ取り込みます。下書きを公開するまで端末表示は変わりません。[接続設定と検証範囲](docs/upstream.md)を参照してください。新FIDS APIはWeb側への設置が必要で、本番接続はまだ行っていません。MKM Flight WebのDBは習志野の本宅にあり、DB移転は前提にしません。
