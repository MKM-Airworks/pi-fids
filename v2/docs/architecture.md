# V2 設計方針

## 変更境界

既存MKM Flight Webの配信API、JSON契約、他製品向け公開版は原則変更しません。既存inspection-record契約は出発ダイヤ用であり、到着・当日運航情報を追加しません。V2の完全なFIDS契約、クラウド保存・同期は独立して追加します。V1のコード・依存関係は直下に保持します。

## ローカルだけで展開できる構成

スタッフのブラウザー → 空港内管理PC → LAN → 各FIDS。

管理PCでダイヤ・当日変更を編集し、下書きと公開版を分けて配信します。表示クライアントはフライト情報、表示指示、ロゴ・案内画像を取得して保存します。クラウド移行が間に合わなくてもローカル運用とバックアップ・復旧で導入可能にします。

表示指示はモニター単位です。便一覧、航空会社・受付区分、搭乗口・優先搭乗・Zone・矢印を設定し、左右画面のグループ切替を行います。指示の版と端末の反映応答を管理します。公開前にプレビューし、期限・終了条件で待機画面に戻します。

表示言語は日本語、英語、中国語、韓国語の4言語。中国語は繁体字・簡体字の表記を設定で選べます。端末ごとに固定言語、切替対象と順番、切替間隔を保存します。見出し・状態・案内文・空港名を翻訳対象とし、便名・時刻・航空会社コードは共通値を維持します。未翻訳の文字列は英語へフォールバックし、表示前にプレビューできるようにします。画像に埋め込まれた文言は自動翻訳せず、言語別画像を登録します。Windows x86/x64とPiで日中韓のフォント・文字欠け・長文の収まりを検証します。管理画面の多言語化は表示画面とは別に範囲を決めます。

### フライトごとの言語設定

管理画面でスケジュールごとに使用言語、表示順、切替間隔を保存します。単一言語は固定表示、複数言語は指定順に切り替えます。中国語は繁体字・簡体字を区別します。同じ便名でも期間の異なるスケジュールを区別し、設定は組織・空港・スケジュールIDに紐づけます。必要に応じて運航日別の変更を設定でき、変更はその運航日にだけ適用します。

優先順位は運航日別設定 → スケジュール設定 → 端末の既定設定です。未設定は継承を意味し、空の言語一覧を設定値として保存しません。航空会社別プリセットは編集時に設定をコピーする補助機能とし、プリセット変更で公開済みの便設定を自動変更しません。

例：日本国内便は日本語・英語、台湾便は中国語（繁体字）・英語、韓国便は韓国語・英語。路線や航空会社から自動決定せず、担当者が選びます。

便一覧の見出しは端末設定に従い、各行の行先・状態・案内はその便の設定で切り替えます。各行の切替は別に管理し、設定の異なる便が混在しても画面全体の言語を強制変更しません。カウンター・搭乗口は選択した運航便の設定を使います。対象便未選択の航空会社案内・待機画面は端末の既定設定を使います。

便の言語設定は公開版・バックアップに含め、変更はプレビューして公開した後に反映します。LAN用V2契約で扱い、既存MKM Flight Webの配信形式には追加しません。未翻訳時の英語へのフォールバックは便の設定を上書きせず、管理画面に翻訳不足を表示します。

## 二つの正本モード

- Webメイン：クラウドで編集・公開し、管理PCが検証・保存・LAN配信。ローカルのフライト編集を禁止します。
- 空港内メイン：管理PCで編集・公開し、クラウドへバックアップ。通信断中も編集・公開を継続し、未送信キューを再送します。

両モード、バックアップ、復旧、正本切替は今回の実装範囲です。クラウド機能未導入時は空港内メインだけを使用します。バックアップと他製品への公開は別操作です。

正本は組織・空港ごとに一つ。公開版は組織、空港、管理世代、版、本文ハッシュで識別します。別正本の版番号を単純比較しません。通常切替では旧正本の編集停止、最終版照合、取込み、新管理世代への切替、端末反映確認を行います。障害時も担当者が旧正本の停止・切離しとバックアップ時点を確認して切り替えます。旧PCの復帰による二重配信は拒否します。自動正本切替は行いません。

## データと保存

シーズナルダイヤと運航日別変更を分離し、出発・到着、定刻・見込・実績時刻、航空会社・コードシェア、ゲート・カウンター、運航・搭乗状態を扱います。不明値を推測しません。欠航便は欠航として表示します。

空港タイムゾーンを設定し、端末のOS時刻帯ではなく空港現地日付で展開します。SHI・RORの境界、運航曜日、深夜便を検証します。RORは既存のAsia/Tokyo限定公開処理に依存せずV2契約で扱います。

検証後に原子的に適用し、失敗時は最終正常データを保管します。有効期間と鮮度を評価し、期限切れのダイヤを現在有効として扱いません。

ロゴ・案内画像はフライト本文と別管理し、コード・用途・版・サイズ・ハッシュで検証します。標準画像を同梱し、取得失敗時は保存済み画像を維持します。

バックアップはデータ、下書き、公開版、表示設定、画像、履歴を一貫した単位で保存します。ローカルの別媒体とクラウドを区別し、同一PC内の保存だけを故障対策としません。暗号化、保持期間、許容損失時間を確定します。復旧は別領域で整合を検証し、プレビュー、資格情報再設定、旧PC無効化、端末反映確認後に再開します。

## 認証と運用

スタッフの操作権限、公開権限、端末読取権限、クラウドバックアップ権限を分離します。上流トークンは管理PCで保管し、表示端末へ送信しません。組織・空港の分離、変更履歴、未反映・未送信・最終成功時刻を確認できるようにします。

RORは訪問を前提にしません。仕様とLANを遠隔確認し、手元で同等環境を検証、設定済み配布と診断情報を用意します。実際のPC・LANの最終確認は遠隔で行います。
