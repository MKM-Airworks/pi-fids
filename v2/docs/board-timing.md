# 便一覧の並び順と表示終了（V2）

出発便はSTD、ETDがある場合はETDで昇順に並べる。到着便はSTA、ETAがある場合はETAで昇順に並べる。同じ時刻は便名順。実績時刻は並び順に使わない。

表示終了の基準時刻は実績時刻（出発ATD／到着ATA）を優先し、未入力なら予定時刻（ETD／ETA）、未入力なら定刻（STD／STA）を使う。出発は既定10分、到着は既定120分を加えた時点で非表示になる。旅客画面は約1秒ごとに判定し、通信停止中も保存済み便に同じルールを適用する。管理画面の下書き・公開済み便は残し、削除しない。

管理画面の「端末の表示切替」で画面IDを選択し、出発便・到着便の表示終了時間を変更して「この画面に適用」を押す。設定は画面ID・空港ごとに0～10080分の整数で保存し、便の公開操作は不要。表示モード・ロゴ・案内画像も同じ操作で適用される。受信端末にも配信し、管理端末・受信端末の再起動後も保持する。

便の運航日は必須。予定時刻・実績時刻の日付は未入力なら運航日を使う。例えば10月5日23:55の便が翌日00:15へ遅延する場合、予定時刻00:15、予定時刻の日付10月6日を指定する。SHI・RORはともにUTC+09:00を使い、PCやブラウザのタイムゾーンには依存しない。表示開始時刻の制限は今回追加せず、公開した将来便も表示対象になる。

Web取込みでは選択した運航日を各便に保存する。同日の再取込みは端末管理で入力した実績時刻・日付を保持し、別の運航日への取込みでは実績時刻を引き継がない。現行Web配信にはATD／ATAがないため、今回の実績時刻は管理画面で入力する。MKM Flight Web側のAPI・データ形式は今回変更しない。

旧V2試験データの運航日がない便には、最初の更新後起動時に空港の当日を一度だけ付与する。古い便が翌日再表示されることを防ぐための移行であり、過去便・翌日便は管理画面で日付を確認して必要なら修正・公開する。V1には変更しない。

検証: `python3 -m unittest discover -s tests`、`node --test tests/board-policy.test.cjs`。境界時刻、ETD／ETAへの切替、ATD／ATA優先、設定値、日付またぎ、保存・再起動・受信端末、Web再取込みを含む。Windows実機でのKiosk確認は別途必要。
