# サンプルに基づく表示再構成

参照元：[Display Image Sample](https://drive.google.com/drive/folders/1dlMcEghUw3bOxZYnwookYk1JBPjiWBVH)。HAN DS3 v4のスライド54・55・58の画面例、HAN T2 v3のスライド19・20・21・25の設置写真、航空会社ロゴを確認した。

## 初期テンプレート

- **便一覧**：濃紺背景、青い見出し、交互の行色、定刻の黄色表示、右上の空港現地時刻、下部の空港・日付・ページ番号。15秒ごとに次ページへ切替。端末設定で1ページ4〜16便、標準8便。ブラウザ全体に追従する。
- **航空会社ロゴ**：カウンター／搭乗口の見出しと大きなロゴ。素材を変形・切り抜きせず元の縦横比で表示する。ロゴがない場合は航空会社名の文字表示。
- **全面案内画像**：画像内に既に案内が含まれるため、画面側の見出し・時計・航空会社名・フッターを隠す。素材全体を比率保持で表示する。画面と画像の縦横比が異なる場合は黒い余白を許容し、切り抜かない。

画面の見た目は `static/display.css`、管理画面は `static/style.css` に分離した。管理画面の編集や端末の受信・保存契約は変更していない。表示画面をオフラインで再起動するための配布対象に新しいCSSを追加した。

## 今回の範囲と今後

便名・行先・定刻の3列に加え、便名の横に航空会社ロゴを表示する。管理画面の便追加で登録済み画像を選び、V2便データの任意項目 `airlineLogo` に画像IDを保存する。未設定の便は便名だけを表示する。端末受信サービスとブラウザ保存の双方が便ロゴも取得し、画像取得に失敗した版は表示に反映しない。航空会社コードによる自動割当は未実装。

サンプルにあるETA/ETD、運航状態、ゲート、カウンター、コードシェア、到着便を未提供の値で補わない。これらを加える際はV2側のデータ契約と表示設定を拡張し、MKM Flight Web既存APIには変更を加えない。

Hanoiの2画面並列表示を参考にした便情報＋航空会社の対表示、便割当、クラス・優先搭乗・矢印は次の機能追加。今回のロゴ画面には便の行先や便名は出さない。表示の行先翻訳データは引き続き未実装。

Macの試験画面で、10件の架空便による2ページの切替、ANAロゴの大きな表示、全面案内画像で追加文言が出ないことを確認。素材は一時試験DBに登録し、製品リポジトリへ画像自体を転載していない。Windows Kiosk実機と設置画面の解像度確認はこれから。
