# CA不要のローカル配信

## 構成

管理PCのブラウザ → localhostの管理サービス → SQLiteの公開版 → 読取専用HTTP配信 → LAN → 端末受信サービス → 端末ディスク → localhostのEdge Kiosk。

管理画面は常に127.0.0.1で待ち受ける。LAN側は `/api/feed` と `/asset` のGETだけを公開し、下書き・編集・管理画面は提供しない。端末は空港と画面IDに限定した接続キーを持つ。便と表示指示は同じDB読取スナップショットから取得し、必要な画像が揃ってから端末で適用する。管理PC上のプレビューはログインしたブラウザから開く。

CA証明書の発行・配布は不要。LANのHTTPは暗号化されず、接続キーと公開情報は通信を読める相手に見える。信頼できる閉じた空港LANで使い、配信ポートをインターネットへ公開しない。端末画面はlocalhostなのでブラウザの保存機能を利用できる。空港LANのファイアウォール設定とWindowsのファイル権限は導入時に確認する。別のPCから管理画面を開く機能は今回の構成に含まない。

## 管理PCの初期設定

以下は `v2` ディレクトリ内で実行する。SHIの設置ではRORをSHIに変更する。ファイル名は例。1管理インスタンスを1空港に限定する。

```sh
python3 -m pifids.security init --config manager-auth.json --airport ROR --username admin
```

画面に従い12文字以上のパスワードを2回入力する。ファイルにはソルト付きPBKDF2-SHA256のハッシュを保存し、平文パスワードは保存しない。既存ファイルの上書きは拒否する。

```sh
python3 -m pifids --auth-config manager-auth.json --lan-port 8803
```

管理画面は `http://127.0.0.1:8800/`。管理ログインは最大8時間有効で、ログアウトで失効する。ログイン失敗が1分間に5回あると、同じ接続元の再試行を制限する。起動時に `--lan-host` でLANの特定IPへ絞ることもできる。`--auth-config` なしではLAN配信を起動できない。既定の認証なしlocalhost試作も引き続き使用できる。

ログイン画面はPi-Access Proと同じ空港背景・青いオーバーレイ・白いカード・MKM Airworksロゴを使用する。背景とロゴをFIDSに同梱するため、外部サイトへの画像取得は不要。英語を既定に、日本語への切替を管理ブラウザに保存する。

## 端末の接続ファイルを発行

管理PCのLANアドレスを固定・予約してから実行する。`192.168.1.20` は例なので実際の管理PCアドレスへ置き換える。

```sh
python3 -m pifids.security terminal --config manager-auth.json --display-id gate-01 --source http://192.168.1.20:8803 --output gate-01.connection.json
```

端末ごとに実行し、出力ファイルだけを対象端末へ安全にコピーする。管理用設定ファイルはコピーしない。接続ファイルには接続先・空港・画面ID・ランダムな接続キーを保存する。管理側には接続キーのSHA-256ハッシュだけを保存する。同一画面IDの再発行で旧キーは失効する。接続ファイルの既存ファイルへの上書きは拒否する。資格情報ファイルをGitや共有の資料フォルダに保存しない。macOS/Piでは所有者だけ読める権限で生成する。Windowsでは管理用アカウント・受信サービスの実行アカウントだけが読めるようファイル権限を設定する。

端末上で起動する。

```sh
python3 -m pifids.receiver --connection gate-01.connection.json
```

画面URLは `http://127.0.0.1:8801/display?airport=ROR&displayId=gate-01&kiosk=1`。接続キーはブラウザに送らない。配信先のリダイレクトは拒否し、他のホストへキーを転送しない。従来の同一PC試験用 `--source`・`--airport`・`--display-id` による起動も継続できる。

## 紛失・交換した端末のキーを停止

```sh
python3 -m pifids.security revoke --config manager-auth.json --display-id gate-01
```

管理配信を再起動しなくても次のリクエストから拒否する。失効した端末に保存済みの画面を遠隔消去する機能ではなく、新規受信を停止する機能。端末は最後の正常表示を保持する。

## 検証と残る作業

Macで管理ログイン・空港制限・公開版のみの配信・画像受信・画面ID制限・キー失効・受信失敗時のディスク保持を通信試験した。Windows/Piの別PCでのLAN通信、ファイアウォール、実機Kiosk、サービス化・自動起動・監視は未検証。複数スタッフの個別アカウントと権限、変更履歴、端末反映応答、正本切替、MKM Flight Web取得・クラウドバックアップは後続実装。既存MKM Flight Web APIとV1コードは変更していない。
