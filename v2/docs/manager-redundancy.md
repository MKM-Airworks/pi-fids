# 管理PC 2台構成と故障時の引継ぎ設計

設計日：2026-10-09。専用サーバーを追加せず、管理PC A/Bで主系・待機系を構成する。これは設計資料であり、2台運用の実装・実機検証完了を意味しない。

## 通常運用

| 機器 | 役割 |
| --- | --- |
| 主系A | 編集・公開の正本、Web受信、表示端末への配信、待機系への複製 |
| 待機系B | 主系へ接続してユーザー操作。復旧用の複製を保持。自身の編集・公開・Web受信・端末配信は停止 |
| 表示端末 | 主系から取得して端末ディスクへ保存。通信断中も最後の正常データと画像を表示 |

正本は組織・空港ごとに必ず1台。Web自動受信・公開は主系だけが行う。待機PCからの通常操作は主系の認証・権限・監査ログを通す。主系に届かない間は待機PCで独立した編集を始めず、管理者の引継ぎを待つ。

既存の管理画面はlocalhost限定で、LAN配信口は読取専用。2台目の操作のために管理画面を未暗号化HTTPでLANへ公開しない。初期案は認証付きSSHトンネルでBのlocalhostからAのlocalhostへ接続する。専用接続アカウント、転送先制限、ホスト鍵確認、再接続とログアウトを導入・検証する。トンネルは通信保護であり、アプリ側の個別ログイン・権限・監査を省略しない。運用しやすさの実機確認後に方式を確定する。

## 複製とバックアップ

初期設計値は変更確定後の複製＋60秒ごとの照合。待機PCへの最終成功から60秒以内を通常時の損失目標とする。通信断中はこの目標を保証せず、最終複製時刻・遅延・失敗を両PCに表示する。故障から操作再開までは10分以内を目標に、実機試験で測定する。

複製対象：下書き・公開便、当日変更、航空会社・空港名、画像、端末登録・表示指示・表示時間帯・既定画像・言語設定、ユーザーと権限、監査ログと保持設定、Web連携モード・最終取得版、時刻同期設定。パスワードはハッシュのまま扱い、ログインセッション・実行中ジョブ・一時ファイルは引き継がない。

SQLiteの一貫したスナップショットを取得し、必要画像の一覧・サイズ・ハッシュ、組織・空港、管理世代、版、アプリとDB形式のバージョンを付ける。稼働DBファイルの単純コピーや共有フォルダー上のDB同時使用はしない。待機PCの隔離領域で検証後に原子的に保存し、正常な旧複製を壊さない。複製の成功は待機側の受領・検証応答で判断する。

上流受信トークン、端末認証設定、複製資格情報は通常資料と分離し、暗号化された転送と両PCの限定ファイル権限で保管する。主系・待機系間の複製権限は空港と操作を限定し、端末の読取キーを複製・管理認証に使わない。Bで上流認証を利用可能かは設置時に確認する。

複製は誤操作・破損も伝播するため、独立した世代バックアップをUSBなどPC外にも保管する。初期案：毎日1回・7世代、切替直前にも取得。監査ログの72時間などの保持設定とは別にバックアップ保持を表示し、バックアップ内に残る監査情報の期間も運用規程で決める。

## 表示端末の接続と管理世代

A/Bは固定または予約IPとし、各端末には両方の候補と端末専用キーを事前登録する。IPアドレスの取り合い・障害時の同一IP付替えを基本手順にしない。候補への到達性だけでは主系へ昇格しない。

配信契約へ管理PCの識別子、空港、管理世代、版、本文ハッシュを追加する。端末は承認済み世代・管理PCを永続保存し、旧主系や承認していないPCの配信を拒否する。世代の異なる版番号を単純比較しない。引継ぎは新世代と候補Bの明示承認を端末へ渡す専用処理で行う。接続キーのある応答だけで世代変更を受け入れない。引継ぎ指示の認証・再送拒否・端末ごとの受領記録を実装する。

未接続端末は引継ぎ指示をまだ受けていないため、自動的に二重配信防止が完成したとは扱わない。旧主系の物理的・ネットワーク的な切離しを引継ぎの必須条件とし、未反映端末は一覧に残す。Bへの切替後も端末の保存済み表示を消さず、新規データと画像が揃った時だけ更新する。

## 故障時の手順（管理者）

1. 主系の停止を確認し、電源OFFまたはLAN切離しを実施する。通信断だけでは故障と断定しない。旧主系を確実に隔離できなければ昇格せず、表示端末の保存済み表示を継続する。
2. Bで「管理を引き継ぐ」を開く。対象空港、旧主系、最後の正常複製時刻・版、未同期による損失の可能性を確認する。
3. 隔離した複製の整合性・画像・ソフトウェア互換性を検査し、復旧前バックアップを保存する。復旧データをプレビューする。
4. 管理者が旧主系の隔離を確認して昇格する。新管理世代を発行・記録し、Bの管理・配信を開始する。Web受信資格情報と接続状態を確認する。
5. 表示端末をBへ切り替え、各端末の世代・反映版・最終応答を確認する。未反映端末は現地接続ファイル更新で対応する。全部成功するまで「切替完了」にしない。
6. 同期済みより新しいWeb公開版の有無を確認する。空港内で行った未複製の手動変更はWebから戻らないため、必要に応じて再入力する。

引継ぎ処理は段階と結果を永続保存し、中断後は同じ引継ぎIDで再開する。途中失敗を隠して通常画面へ戻さない。昇格後に旧世代を自動的に再有効化しない。引継ぎ・損失時点の確認・端末反映・資格情報の再設定は操作者と日時を監査へ記録する。

## 旧主系の復旧

旧PCはLANに戻す前に待機状態へ変更し、配信・Web受信・書き込みを停止する。旧データを現在の主系へ自動マージしない。必要な未同期変更は別領域で比較し、管理者が現在の主系へ再入力する。その後、新主系から正常な複製を受けて待機として参加する。役割をAへ戻す場合も、正常な計画切替手順を別途実行する。

オフラインの2台だけでは、通信断と故障の完全な自動判別や、隔離されていない旧PCの停止を保証できない。専用の仲裁機器は置かず、手動確認と旧主系の隔離を採用する。

## 管理画面

管理者専用の「冗長構成・バックアップ」を追加する。既存の①〜⑧の番号は変更せず、追加設定として配置する。主系／待機、接続先、空港、管理世代、最終複製時刻と成否、バックアップ日時、未反映端末を表示する。操作は「接続試験」「今すぐ複製」「バックアップ」「復元」「管理を引き継ぐ」。オペレーターは通常の便情報・表示切替だけを操作し、昇格・復元・接続変更は管理者に限定する。

引継ぎ画面は時刻・欠落の可能性・旧主系隔離の確認を明示し、最終確認のあとに実行する。通常のユーザー操作は主系の同じデータを見せ、同時編集では古い下書き版からの上書きを拒否して再読込みを求める。

## 現在の実装との差分と実装順

確認済み：receiver.pyは便・画像をローカル保存し、取得失敗時に正常表示を保持する。localhost管理と読取専用LAN配信、ユーザー権限・監査の基盤がある。

追加が必要：2台目の安全な管理接続、一貫した複製、資格情報の保護、バックアップ復元UI、主系・待機の起動制御、管理世代付き配信、認証された端末接続先切替、引継ぎ記録、旧主系復帰制御。現行receiverは単一sourceと版番号比較であり、そのままでは新管理世代の切替を実現できない。

実装順：①バックアップ・復元と整合性検証 → ②主系／待機の役割制御と複製 → ③2台目からの通常操作 → ④管理世代・端末切替 → ⑤引継ぎUIと日英手順書 → ⑥実機故障試験。自動昇格は実装しない。

## 受入試験

- 主系電源断でも、表示端末の再起動後に保存済み画像・便を表示できる。
- 待機への復旧は便、画像、ユーザー権限、端末設定を保ち、未複製の範囲を明示する。
- 通信断だけで昇格しない。未承認世代、旧主系の再起動、旧配信の再送を端末が拒否する。
- 未接続端末の復帰、画像欠落、破損バックアップ、異なる空港、DB形式違いを安全に扱う。
- 引継ぎの各段階で中断・再実行しても二重配信を開始しない。
- 待機PC経由の操作にも個別権限・監査・同時編集拒否が効く。
- Web断・LAN断・両PC断・日付変更では最終保存を維持し、古い便情報の鮮度を別途評価する。保存継続を最新情報の保証と混同しない。
- 60秒の損失目標と10分の復旧目標を実測し、結果を日英手順書へ反映する。
