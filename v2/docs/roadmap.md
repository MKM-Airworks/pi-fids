# 開発順序と受入条件

## 1. データ契約と実行環境

共通データ契約、管理世代・版識別、空港時刻、認証、公開単位を定義します。Windows 10 x86のPython・依存ライブラリ・ブラウザーの成立を早期確認します。本宅にWindows端末があるため、当面はMacで共通開発を進めます。

## 2. 最初の実行可能な縦断機能

管理画面で試験便を登録・公開 → LANフィード → クライアント表示 → 航空会社案内の切替 → 反映応答、を一通り動かします。SHI・RORの合成データを使います。

## 3. ローカル単独展開

到着・当日変更、端末設定、左右画面切替、画像配信、永続保存、権限、ローカルバックアップ・復旧、再起動復帰を完成させます。クラウドなしで導入できることを確認します。

## 4. クラウド接続と両モード

現行試験環境でWebメイン、クラウドバックアップ、再送、復旧、正本切替を開発します。Render等へのDB移行は別工程です。既存APIの互換性を保ちます。

## 5. OS検証と段階導入

Windows 10 x86/x64、Windows 11 x64、Piで起動・表示・自動起動・再起動・更新復帰を確認します。SHI・RORの導入順は現地条件で決めます。

## 必須の検証

- 公開版だけが配信され、下書きが表示されない。
- 組織・空港を越える編集・受信・バックアップ取得を拒否する。
- 通信断中もローカル公開と表示切替ができる。
- 破損データ・画像・バックアップを適用しない。
- 再送による重複公開、旧管理世代の配信、二重正本を拒否する。
- バックアップから別PCへ復元し、端末反映まで確認できる。
- 空港日付・曜日・深夜便、期限切れ、表示指示の期限を正しく扱う。
- 指示送信と端末反映を区別し、失敗を管理画面で確認できる。

各段階は今回の実装範囲内の検証順序です。V2リリースは両モードの検証後とし、クラウド移行が遅い場合は機能を明示したローカル導入版を先行配布します。
