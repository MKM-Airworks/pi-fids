# MKM Flight Web → Pi-FIDS 配信認証・権限制限の確認記録

確認日: 2026-10-09（日本時間）

## 結論

SHIの実機接続で、Pi-FIDS受信トークンによる配信データの取得は成功し、フライト保存・公開APIへの書き込みは拒否されました。受信APIは読み取り専用です。認証の実行場所はWixではなく配信サーバーです。

| 確認事項 | 結果と根拠 |
| --- | --- |
| 毎回Bearerを検証するか | manifest・releaseのGETごとに配信サーバーのreceiver_scopeで検証。304応答の判定より先に認証する。 |
| 空港ごとに異なるか | 資格情報は組織・空港・製品pi-fidsに固定して個別発行する実装。今回の実機確認はSHI。全空港の発行一覧・別空港を横断する実機試験は対象外。 |
| 読み取り専用か | 受信経路はGETのみ。保存・公開は別の会員署名と権限を要求し、受信トークンでは認証できないことを実機確認。 |

## 認証と権限の分離（コード確認）

- Pi-FIDS管理PCはHTTPSのPullで受信する。manifestとreleaseの両方にBearerを付ける。
- 配信サーバーはトークン形式、資格情報の失効・有効期限、SHA-256ハッシュとの定時間比較、組織・空港・契約製品の有効状態を確認する。
- 新規資格情報には32バイトの乱数を使う。空港スコープは資格情報DBに固定され、要求側から他空港へ変更できない。別組織・空港の配信版は取得対象外となる。
- 資格情報DBにはトークンのハッシュを保存する。受信トークンはWix会員用署名や開発用トークンとは別系統で、管理・編集用認証には流用されない。
- Wixからの保存・公開は会員署名と対応する権限を使用する。Pi-FIDS受信資格情報とは分離されている。
- 配信内容は公開用フライト項目に限定し、内部備考・検査業務項目を含めない。公開版のUPDATE・DELETE禁止はDB定義で確認した（稼働DBへの変更試験は未実施）。

## 実機API確認

Win11管理PCから、設定済みHTTPS配信先 https://api.mkmairworks.online のSHI資格情報を使用した。秘密値は出力・記録していない。書き込み拒否の確認には空のJSONを使用し、実データの変更・削除は行っていない。

| 試験 | HTTP結果 |
| --- | --- |
| 正しい受信トークンでmanifest GET | 200 |
| トークンなしでmanifest GET | 401 |
| 1文字変更したトークンでmanifest GET | 401 |
| 正しい受信トークンでrelease GET | 200 |
| 受信経路へのPOST / PUT / PATCH / DELETE | 各405 |
| 受信トークンで公開APIへPOST | 401 |
| 受信トークンでフライト保存APIへPOST | 401 |
| フライト保存経路へDELETE | 405 |

## 確認範囲と運用

期限切れ・失効・契約無効時の拒否と、別組織の配信版の拒否はコード・既存契約試験で確認した。稼働中の資格情報を失効させる実機試験、全空港の資格情報棚卸し、包括的な侵入試験は今回実施していない。

受信トークンが漏洩した場合、その空港に限定した配信データが期限切れまたは失効まで読み取られる可能性は残る。漏洩時は該当資格情報を失効・再発行する。受信トークンの秘密値・資格情報ファイルは共有DriveやGitHubへ保存しない。本記録にも秘密値を含めない。
